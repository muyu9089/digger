# 澄明 · 个人投资工作台

依据 `个人投资工作台_第一版需求与页面流程.md` 开发的单用户第一版。Python 标准库、SQLite、原生网页，无第三方运行依赖。账务计算使用 Decimal，输入最多 12 位小数，输出统一为 12 位定点数；界面金额通常显示两位小数，原始值可在记录和备份中查看。

## 启动

需要 Python 3.10 或更高版本，在项目目录执行：

```powershell
python app.py --init
python app.py
```

第一条命令交互设置至少 12 字符的密码；无默认密码和公开注册。浏览器访问 http://127.0.0.1:8765 。另开一个终端运行后台任务：

```powershell
python app.py --worker
```

两个进程共用 `data/workbench.sqlite`，任务并发上限为 1。若使用 `--db` 指定数据库，两个进程必须指向同一路径。默认不启用任何计划，不导入示例资产，不发送任何真实持仓。密码也可以通过服务端 `INVEST_PASSWORD` 环境变量初始化；初始化后应移除此变量。

## 日常操作

1. 在“账户与持仓”新增账户和证券映射，明确市场、代码、币种、数量单位、计价乘数。可转债按所用数量单位设置乘数。
2. “导入期初数据”：添加期初现金和持仓，或读取 `.xlsx`，选择工作表、账户、行号和代码/份额/成本列。只读读取源文件；公式不使用缓存入账，日期序列不自动猜测。名称不能替代证券代码和市场。
3. 保存草稿，查看逐项来源、现金对账控制数和试算，确认后才建立资产。重复批次或已确认的同源文件阻止再次导入。草稿可修改；已确认批次可撤销，若撤销破坏后续账务则阻止。
4. 用“记一笔”录入实际变动，预览现金和持仓后确认。费用未知时保存草稿；不能用零代替未知。红利再投资支持场外基金；现金分红单独记录。换汇的实际扣款已经包含费用，另存费用作为依据。
5. 基金申购依次记录申请、实际扣款、确认；赎回依次记录申请、确认、到账。确认后不重复计算持仓与在途/应收。
6. 手工维护有日期和来源的行情/汇率。过期值保留并提醒；更旧的值不能覆盖较新的有效值。超过三个日历日标为过期，这是保守的第一版规则，并非交易日历判断。
7. 用款计划必须指定固定日期和包含关系。累计目标按阶段增量匹配现金；独立支出逐笔消耗现金；基础和购房等情景各自计算。仅使用当日核验的可取现金，尚未预留资金，也不宣称用款已保障。
8. 亏损基准需要确认日终日期、完整人民币总资产。基准日之后的外部投入调整亏损，内部转账不调整。外币外部资金流必须提供当日折算汇率。历史数据缺失或过期时不触发正式亏损告警。
9. 报告保存生成时持仓、证券理由、来源、模型配置摘要和消耗。采纳/暂缓/不采纳只保存决策，不生成交易。已入账记录修正保留原值，按日期重算后续；旧研究快照不被改写。

## 模型与资料配置

密钥只从服务端环境变量 `INVEST_MODEL_KEY` 读取。不会返回浏览器、进入普通日志或写入备份。页面设置模型完整 HTTPS 接口地址、模型名、计费单价和预算；必须勾选数据发送授权。当前协议为 Chat Completions：POST `{model,messages,max_tokens}`，响应 `{choices:[{message:{content},finish_reason}],usage:{prompt_tokens,completion_tokens}}`。不依赖特定模型厂商。

发送字段：研究问题、深度、持仓快照、证券信息、投资理由、来源资料。测试连接与研究都是真实调用；测试不发送持仓。研究预算按美元配置，按填入的单价和输入字节保守估算、限制输出 token；实际费用记录来自返回 usage。每天按上海时间累计预留预算，失败或取消也保留预算，避免反复重试超支。服务商额外收费、特殊 tokenizer 或单价变动无法由本程序保证，应同时配置服务商额度上限。后台中断不能保证远端调用未计费。

资料有两个入口：研究表单填写 `{url,date,text}` 来源数组，或在设置中配置自建 HTTPS 资料服务。资料服务接收 POST `{security,question}`，返回 `{sources:[{url,date,text}]}`。内容只作为证据；不读取其中的操作指令。这里尚未提供任何市场公告抓取器，不承诺自动获取最新公告。没有资料、远端失败或响应不完整时保存失败/部分完成记录，不能输出已获支持的成功结论。股票与基金使用不同研究提示；同资料、持仓和问题复用有效报告。

计划在页面显式启用，按指定的每日/每周上海时间运行。目前基于日历日，不支持真实市场交易日和公告更新触发；规则检查因此标为“部分完成”，提醒资料检查未完成。任务状态和失败原因可查看，失败可重试，排队可取消。同一事件的快照和通知去重；同标的并发任务合并。

进程中断后，先停止旧 worker，再执行：

```powershell
python app.py --recover-tasks
python app.py --worker
```

中断任务标为失败，核验服务商调用记录后手动重试。

## 备份与独立恢复

在设置页面下载完整 JSON 备份，包括账本、模型与资料配置（不含密钥）、报告、资料文本、决策、任务、审计和账户属性。SHA-256 用于发现误损坏，不是加密或恶意篡改的身份认证。备份含财务资料，应由部署环境控制存储访问。

```powershell
python app.py --db data/restored.sqlite --restore investment-backup.json
python app.py --db data/restored.sqlite --init
python app.py --db data/restored.sqlite --port 8767
```

仅允许恢复到空数据库。恢复在一个事务内执行，校验摘要、现金、持仓、在途、已实现损益、资金流、总额和决策关联；不匹配即回滚。密码与环境密钥需要独立重新配置。程序不接收浏览器直接覆盖生产库的恢复请求。

## 云端部署

提供 `Dockerfile` 和 `compose.yaml`，web 与 worker 共用数据卷。仅将 HTTP 端口映射到服务器回环地址，在前面配置 HTTPS 反向代理（示例 `deploy/nginx.conf.example`）。先修改真实域名、配置证书和服务端密钥，再运行：

```sh
docker compose build
docker compose run --rm web python app.py --init
docker compose up -d
```

Compose 默认 `INVEST_SECURE_COOKIE=1`，应通过 HTTPS 访问。证书、域名、服务器规格和密钥未提供，当前没有进行云端部署或证书配置。数据库卷及备份目录只授予服务账户访问，定期将备份复制到独立存储。不要公开直接暴露 Python HTTP 端口。


验收测试覆盖 AC01—AC14；研究通过模拟服务响应验证，未消耗真实 API。补充测试覆盖现金/持仓不足、费用未知、小数和移动加权成本、历史修正回滚、过期价格、用款去重、密码与备份篡改、Excel 公式保留。

## 当前交付范围与未接通项

七个主页面与期初导入、交易预览、持仓详情、研究版本、决策、通知和设置已实现。账户与全组合集中度可检查，行情、行业依据和平台参考收益手工维护。数据不足时显示不完整，平台收益不计入账本。

仍待真实环境接入：用户最新 Excel 正式迁移、行情和公告数据源、模型连通性与真实股票/基金研究、交易日历、云端 HTTPS 与现场恢复演练。资金预留、基金赎回期限与穿透数据未自动核验。期间投资损益提供已确认基准日终至当前的金额口径；任意历史期间对照、回撤及收益率未实现；不会输出缺少依据的收益率。文件附件目前仅支持资料文本，不支持独立二进制上传。原需求文档保留不变，不将未确认的日期、模型、任务频率静默设为正式配置。
